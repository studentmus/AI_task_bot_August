August AI Assist — Полный технический контекст проекта

  Дата редакции: 17.05.2026

  ---
  Что это

  Асинхронный Telegram-бот на Python 3.11+ (aiogram 3.x). Единый интерфейс
  для управления задачами, Google Calendar и базой знаний (Obsidian/MyBrain).
  Гибридная архитектура:
    - Логирование по сферам → детерминированный FSM (без LLM)
    - Задачи и календарь → LLM tool-calling (DeepSeek)

  Dev: Windows 11 + WSL2, рабочая директория /home/adminlinux/AI_task_man
       conda activate taskbot (Python окружение)
  Prod: Ubuntu 24.04 VPS /opt/AI_task_bot_August, systemd unit taskbot.service

  ---
  Стек

  Бот          | aiogram 3.x
  LLM          | DeepSeek API, deepseek-chat, tool calling
  БД           | SQLite + SQLAlchemy ORM
  Календарь    | Google Calendar API — create/update/delete/rename_event
  Планировщик  | APScheduler (CronTrigger + IntervalTrigger)
  Настройки    | pydantic-settings, .env файл
  Obsidian     | Git (add → commit → pull --rebase → push) через asyncio subprocess
  Таймзона     | TASK_TIMEZONE в .env, применяется глобально везде

  ---
  Порядок регистрации роутеров (main.py) — КРИТИЧНО

  1. memory_router   — FSM-ответы на плановые пинги (наивысший приоритет)
  2. log_router      — FSM-логирование по сферам + slash-команды + /undo
  3. motivation_router — /motivate команда
  4. main_router     — NLP-диспетчер свободного текста → LLM

  Внутри main_router: commands_router → tasks_router → dispatch_text

  ---
  FSM Логирование (log_handler.py) — БЕЗ LLM

  СОСТОЯНИЯ (states.py — LogState):
    sleep | nutrition | training | german | romanian | ideas | context | wishlist

  REPLY KEYBOARD (постоянная):
    [🌙 Сон]      [🍽 Питание]   [💪 Тренировка]
    [🌍 Языки]    [💡 Идеи]      [📊 Контекст]

  При нажатии [🌍 Языки] → inline keyboard:
    [🇩🇪 Немецкий]  [🇷🇴 Румынский]
  Выбор языка → входит в LogState.german или LogState.romanian.

  INLINE KEYBOARDS:
    При входе в режим: [✗ Отмена]
    После каждой записи: [✅ Готово] [📝 Ещё] / [↩ Отменить]
      - Готово  → выходит из режима
      - Ещё     → убирает кнопки, сбрасывает таймер, продолжай писать
      - Отменить → удаляет последнюю запись

  АВТОВЫХОД: через 60 секунд молчания → "⏱ Режим завершён — нет активности 1 минуту."
  Таймер сбрасывается на каждой записи и при нажатии [📝 Ещё].

  SLASH-КОМАНДЫ (прямая запись без входа в режим):
    /sleep [текст]    — сон
    /meal  [текст]    — питание
    /workout [текст]  — тренировка
    /german [текст] (/de) — немецкий
    /romanian [текст] (/ro) — румынский
    /ideas [текст] (/idea) — идеи
    /ctx [текст] (/context) — личный контекст
    /wish [текст] (/wishlist) — список покупок
    /stop             — выход из активного режима
    /undo [сфера]     — отменить последнюю запись

  ИСПРАВЛЕНИЯ (май 2026):
    - Slash-команды внутри LogState больше не записываются как лог
      (фильтр ~F.text.startswith("/") на handle_log_entry)
    - "Что сейчас делать" и подобные фразы корректно эскейпят в LLM
      (_LOG_ESCAPE_RE расширен: что делать/нужно/дальше + следующий шаг)

  UNDO:
    /undo [сфера] — удаляет последнюю запись
    Кнопка [↩ Отменить] — инлайн после каждой записи
    Аргументы: sleep/сон, meal/nutrition/питание, workout/training/тренировка,
                german/немецкий/de, romanian/румынский/ro, ideas/идеи,
                ctx/context/контекст, wish/wishlist/список, health/здоровье

  ---
  Бэклог задач (задачи без даты)

  create_task с date=null → статус confirmed, suggested_date=NULL → бэклог.
  LLM получает список бэклога в промпте (build_backlog()) — может предлагать в свободное время.
  next_step engine включает бэклог в контекст → учитывает при рекомендации "что делать".
  14:00 ежедневно: send_backlog_nudge() отправляет случайную задачу из бэклога.
  /undo и complete_task работают с бэклог-задачами как обычно (по task_id).

  ---
  Каскад роутинга свободного текста (dispatch_text в message_router.py)

  Вызывается только при StateFilter(None) — когда пользователь НЕ в LogState.

  Шаг | Триггер                                           | Действие
  -----+---------------------------------------------------+---------------------------
  FSM  | PingState.waiting_response                        | memory_router → _bot/file
  -0.5 | _TRAINING_REFUSAL_RE + энергия >= 5              | motivation_router (пассивный)
  0    | _CANT_SLEEP_RE: "не спится", "бессонница"         | лог health.md + лёгкая рек.
  0.5  | _NEXT_STEP_RE: "что делать", "следующий шаг"      | next_step engine
  1    | _QUESTION_RE: ?, "почему", "есть ли"              | → LLM
  1.5  | _CONVERSATION_RE: "ок", "нет, не надо"            | → LLM как чат
  2    | _OBSIDIAN_LOG_FULL_RE: "запиши в питание: текст"  | → прямой append без LLM
  3    | _OBSIDIAN_LOG_RE: "запиши в питание" (без текста) | → LLM уточнит
  4    | _LOG_CONTINUATION_RE + кэш 15 мин: "ещё съел"    | → прямой append без LLM
  5    | _FACT_VERBS_RE: съел/спал/купил...                | → LLM (complete или log)
  5.5  | _MEAL_NOUN_RE: начало с завтрак/обед/ужин         | → LLM
  6    | COMMAND_KEYWORDS: покажи/перенеси/удали            | → LLM
  6.5  | _CONTEXT_EDIT_RE: "ей/её/эту" (местоимения)       | → LLM (move_task)
  6.7  | _READ_REQUEST_RE: прочитай/что записалось          | → LLM (read_bot_log)
  7    | Fallback: rule-based parse_task()                 | → карточка confirm/reject

  ---
  Ловушки и инварианты

  ПОРЯДОК РОУТЕРОВ: memory → log → motivation → main. Нарушение ломает FSM.

  СОСТОЯНИЯ FSM:
    LogState: sleep, nutrition, training, german, romanian, ideas, context, wishlist
    В LogState dispatch_text не вызывается (StateFilter(None) не проходит).
    В LogState slash-команды работают корректно (~F.text.startswith("/") в handle_log_entry).
    В PingState.waiting_response перехватывает memory_router.

  ЯЗЫКОВОЕ ПОДМЕНЮ:
    "🌍 Языки" не в _SPHERES — отдельный хендлер handle_lang_button.
    _BUTTON_TEXTS = {"🌙 Сон", "🍽 Питание", "💪 Тренировка", "💡 Идеи", "📊 Контекст"}
    Callback "lang:german" / "lang:romanian" → _enter_state с user_id из callback.from_user.

  АВТОВЫХОД ИЗ LОГSTATE:
    _timeout_tasks: dict[int, asyncio.Task] — per-user, хранится в памяти процесса.
    При рестарте бота таймеры теряются (состояние FSM сохраняется, таймер — нет).
    _start_timeout() при каждой записи и входе в режим.
    _cancel_timeout() при явном выходе (stop, done, cancel).

  БЭКЛОГ:
    create_task без date → suggested_date=NULL в SQLite.
    get_upcoming_tasks фильтрует suggested_date >= today → бэклог не попадает.
    get_backlog_tasks фильтрует suggested_date IS NULL.
    Google Calendar sync пропускается для бэклог-задач.

  ПУТИ OBSIDIAN:
    Path(settings.obsidian_vault_path) / "_bot" / filename — не менять.
    append_to_bot_log — прямое имя файла, без SPHERE_MAP.
    append_obsidian_log — через _resolve_sphere(), проверяет существование файла.

  GIT SYNC (obsidian_tools.py):
    Порядок: add → commit → pull --rebase → push (не pull до commit!)
    Все операции сериализованы через _GIT_LOCK (asyncio.Lock).
    Неблокирующий: фоновый asyncio.create_task().

  UNDO МЕХАНИКА:
    Записи вставляются после "## Log" в начало (новые — первые).
    delete_last_log_entry удаляет первую непустую строку после "## Log".
    /undo [сфера] — текстовая команда; [↩ Отменить] — инлайн-кнопка.

  ЗАДАЧИ:
    edit_task_title — только текст, move_task — только дата/время.
    Батч: task_ids=[id1, id2] — один вызов, не два.
    LLM-путь: insert_pending → confirm() сразу → статус confirmed.
    Rule-based путь: статус pending, ждёт кнопки подтверждения.

  ПАРСЕР СНА (log_handler.py):
    Нормализация часов старта: 12→0, 10/11→+12, 6-9→+12 если duration>16ч.
    Остаток текста → комментарий: "23:30-7, хорошо выспался" → "23:30–07:00 (7ч 30м) — хорошо выспался"

  MARKDOWN CLEANUP (_clean_reply):
    LLM может вернуть **bold** — бот использует ParseMode.HTML.
    _clean_reply() удаляет markdown + DeepSeek-теги (<think>, ｜...).

  МОТИВАЦИЯ:
    motivation.md читается синхронно (без кэша — файл редко меняется).

    Если энергия неизвестна или < 5 → триггер не срабатывает, обычный LLM.
