August AI Assist — Полный технический контекст проекта

  Дата редакции: 18.05.2026

  ---
  Что это

  Асинхронный Telegram-бот на Python 3.11+ (aiogram 3.x). Единый интерфейс
  для управления задачами, Google Calendar и базой знаний (Obsidian/MyBrain).
  Гибридная архитектура:
    - Логирование по сферам → детерминированный FSM (без LLM)
    - Задачи и календарь → LLM tool-calling (DeepSeek)
    - Next-step engine → энергия + GCal + алёрты + проекты + что сделано сегодня
    - Просмотр задач → детерминированный DB-запрос (без LLM)

  Dev: Windows 11 + WSL2, рабочая директория /home/adminlinux/AI_task_man
       conda activate taskbot (Python окружение)
  Prod: Ubuntu 24.04 VPS /opt/AI_task_bot_August, systemd unit taskbot.service

  Obsidian Vault (единственный источник правды):
    Windows путь: C:\Users\Admin\MyBrain
    WSL путь:     /mnt/c/Users/Admin/MyBrain   ← используется ботом локально
    VPS:          /opt/MyBrain (или аналог)     ← продакшн-бот
    Все три точки синхронизируются через один git remote.
    .gitignore содержит *:Zone.Identifier — Windows-артефакты не попадают в репо.

  ---
  Стек

  Бот          | aiogram 3.x
  LLM          | DeepSeek API, deepseek-chat, tool calling
  БД           | SQLite + SQLAlchemy ORM
  Календарь    | Google Calendar API — create/update/delete/rename_event/mark_done
  Планировщик  | APScheduler (CronTrigger + IntervalTrigger + DateTrigger для одноразовых)
  Настройки    | pydantic-settings, .env файл
  Obsidian     | Git (add -A → commit → pull --rebase → push) через asyncio subprocess
  Таймзона     | TASK_TIMEZONE в .env, применяется глобально везде

  ---
  Idle Detector (jobs/idle_detector.py)

  In-memory state (сбрасывается при рестарте):
    _last_task_done_at, _last_interaction_at, _idle_ping_sent_at

  mark_task_done()    — вызывается из task_actions.complete_task()
  mark_interaction()  — вызывается в начале dispatch_text()
  snooze_idle(min)    — вызывается из checkin_handler (кнопки idle:rest/busy)

  Условия пинга: since_done >= 45 мин И since_interaction >= 45 мин
                 И нет задач в ближайшие 2 часа И cooldown >= 120 мин
  Кнопки: [📋 Показать план] [😴 Отдых 30м] [✅ Уже занят]

  ---
  Focus/Pomodoro (bot/handlers/focus_handler.py)

  FocusStates.waiting_text — FSM для ввода задачи текстом

  In-memory: _focus dict (active, task_id, task_text, cycle, user_id, paused)
  _end_focus()             — очищает _focus и удаляет job "focus_ping"
  _schedule_ping(bot, uid) — DateTrigger через 25 мин, id="focus_ping"
  _send_focus_ping()       — checkpoint: [+25 мин][✅ Готово][⏸ Пауза 10м][🛑 Завершить]

  Команды: /focus [текст] — если нет текста → selector из задач на сегодня
           /stopfocus — завершить сессию

  Callbacks:
    focus_select:{task_id|custom} — выбор задачи
    focus_task:{task_id}          — кнопка 🎯 Фокус на карточке
    focus:extend                  — ещё 25 мин
    focus:done                    — завершить (если task_id → complete_task)
    focus:pause:{min}             — пауза N мин → DateTrigger "focus_pause_end"
    focus:resume                  — продолжить после паузы
    focus:stop                    — остановить без выполнения

  Требует: scheduler_ref.get_scheduler() != None (set после start_scheduler в main.py)

  ---
  Приоритизация задач

  Поля в Task: urgency INT (1-5), importance INT (1-5)
  priority_score = urgency × importance (1-25)
  Иконки: 🔴 score>=15, 🟡 score>=8, 🟢 score>0, пусто если NULL

  _task_priority_score(task) — защищён от TypeError через try/except int()
  LLM ставит urgency/importance при create_task
  "поставь высокий приоритет" → LLM вызывает set_priority(task_id, urgency, importance)
  /pending и cmd_exec:pending — сортировка по (-score, -id)

  Миграция: старые строковые значения importance ('medium', 'high', ...) → NULL
  (выполняется в _apply_migrations при старте)

  Ловушки и инварианты

  ПОРЯДОК РОУТЕРОВ: memory → log → motivation → main. Нарушение ломает FSM.

  SCHEDULER REF: set_scheduler() вызывается в main.py ПОСЛЕ start_scheduler().
    focus_handler и idle_detector используют get_scheduler() для DateTrigger jobs.
    Если None → одноразовые jobs не регистрируются (фокус не пингует).

  PRIORITY SCORE: всегда через try/except int() — защита от legacy строк "medium" в БД.

  IMPORTANCE FIELD: старое поле importance=String удалено из модели.
    Миграция очищает строковые значения → NULL при старте.

  TASK CARD CALLBACK CONFLICT: cancel_confirm_ и cancel_abort_ регистрируются
    ДО cancel_ в tasks_router (иначе cancel_ перехватит cancel_confirm_ prefix).

  FOCUS STATE: in-memory, теряется при рестарте. _end_focus() удаляет job "focus_ping".
    При рестарте во время сессии — фокус просто перестаёт пинговать.

  MORNING PROTOCOL STATE: _state сбрасывается каждый день при send_morning_protocol.
    Старые кнопки после рестарта работают, но progress не сохраняется.

  GIT SYNC: git add -A (все файлы vault), не только измененный файл.
    Сериализован через _GIT_LOCK (asyncio.Lock). Фоновый asyncio.create_task().

  ЯЗЫКОВОЕ ПОДМЕНЮ: "🌍 Языки" НЕ в _SPHERES.
    Callback "log_sphere:languages" → _lang_kb() → [🇩🇪 Немецкий][🇷🇴 Румынский]

  DAY VIEW: _DAY_VIEW_RE перехватывает "что на сегодня/завтра" ДО step 1 (LLM).
    Использует get_today_plan (pending+confirmed) + get_today_done (summary строка).

  RECURRING GUARD: _RECURRING_RE на step 5.95 перед rule-based fallback.
    "напоминай/каждый/ежедневно" → _run_llm_chat, не parse_task.

  OBSIDIAN PATHS: Path(settings.obsidian_vault_path) / "_bot" / filename
    append_to_bot_log — прямое имя файла
    append_obsidian_log — через _resolve_sphere()
