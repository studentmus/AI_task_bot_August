August AI Assist — Полный технический контекст проекта

  Дата редакции: 16.05.2026

  ---
  Что это

  Асинхронный Telegram-бот на Python 3.11+ (aiogram 3.x). Единый интерфейс
  для управления задачами, Google Calendar и базой знаний (Obsidian/MyBrain).
  Гибридная архитектура:
    - Логирование по сферам → детерминированный FSM (без LLM)
    - Задачи и календарь → LLM tool-calling (DeepSeek)

  Dev: Windows 11 + WSL2, рабочая директория /home/adminlinux/AI_task_man
       conda activate taskbot (Python окружение)
  Prod: Ubuntu 24.04 VPS /opt/AI_task_bot_August, systemd unit taskbot.service

  ---
  Стек

  Бот          | aiogram 3.x
  LLM          | DeepSeek API, deepseek-chat, tool calling
  БД           | SQLite + SQLAlchemy ORM
  Календарь    | Google Calendar API (только) — Radicale УДАЛЁН
  Планировщик  | APScheduler (CronTrigger.from_crontab + IntervalTrigger)
  Настройки    | pydantic-settings, .env файл
  Obsidian     | Git (add → commit → pull --rebase → push) через asyncio subprocess
  Таймзона     | TASK_TIMEZONE в .env, применяется глобально везде

  ---
  Порядок регистрации роутеров (main.py) — КРИТИЧНО

  1. memory_router   — FSM-ответы на плановые пинги (наивысший приоритет)
  2. log_router      — FSM-логирование по сферам + slash-команды + /undo
  3. main_router     — NLP-диспетчер свободного текста → LLM

  Внутри main_router: commands_router → tasks_router → dispatch_text

  ---
  FSM Логирование (log_handler.py) — БЕЗ LLM

  Гибридная архитектура: всё структурированное логирование детерминировано.

  СОСТОЯНИЯ (states.py — LogState):
    sleep | nutrition | training | german | ideas | context

  REPLY KEYBOARD (постоянная, видна всегда):
    [🌙 Сон]      [🍽 Питание]   [💪 Тренировка]
    [📖 Немецкий] [💡 Идеи]      [📊 Контекст]

  FLOW:
    Нажал кнопку → FSM state + data(filename, label) → пиши записи →
    прямой append_to_bot_log → подтверждение + кнопка [↩ Отменить]

    Пишешь другую кнопку → переключаешься в новую сферу
    Пишешь "стоп/выход/готово" или /stop → выходишь из режима
    Вопрос или команда (_LOG_ESCAPE_RE) → маршрутизируется в LLM, не в лог

  SLASH-КОМАНДЫ (прямая запись без входа в режим):
    /sleep [текст]    — сон (с умным парсингом времени)
    /meal [текст]     — питание
    /workout [текст]  — тренировка
    /german [текст]   — немецкий (/de — alias)
    /ideas [текст]    — идеи (/idea — alias)
    /ctx [текст]      — личный контекст (/context — alias)
    /stop             — выход из активного режима

    Без аргументов — входит в FSM-режим соответствующей сферы.

  ПАРСЕР ВРЕМЕНИ СНА (parse_sleep_time):
    Все форматы автоматически конвертируются в HH:MM–HH:MM (Xч Yм):
      23:30-7:00          → 23:30–07:00 (7ч 30м)
      00 30 - 10 10       → 00:30–10:10 (9ч 40м)
      12-8                → 00:00–08:00 (8ч)      [12 → полночь]
      11-7                → 23:00–07:00 (8ч)      [11 → 23]
      9-7                 → 21:00–07:00 (10ч)     [duration-check]
      с девяти до шести   → 21:00–06:00 (9ч)
      с полуночи до 8     → 00:00–08:00 (8ч)
      лег в 23, встал в 7 → 23:00–07:00 (8ч)
      с 00 30 до 10 10    → 00:30–10:10 (9ч 40м)

    Логика нормализации часов старта:
      12 → 0, 10/11 → +12, 6-9 → +12 если duration > 16ч, остальные as-is

    Остаток текста сохраняется как комментарий:
      "23:30-7, хорошо выспался" → "23:30–07:00 (7ч 30м) — хорошо выспался"

  ОТМЕНА ЗАПИСЕЙ:
    [↩ Отменить]    — инлайн-кнопка сразу после каждой записи
                      удаляет первую строку после "## Log" в файле
    /undo           — отменить последнюю запись в активной сфере
    /undo sleep     — отменить в sleep.md
    /undo meal      — в nutrition.md
    /undo workout   — в training.md
    /undo health    — в health.md (записи от пингов)
    Принимает и по-русски: /undo сон, /undo питание

  АВТОСОЗДАНИЕ ФАЙЛОВ:
    Если файл сферы не существует в _bot/ — создаётся автоматически
    с заголовком "# Sphere\n\n## Log\n".

  ---
  Каскад роутинга свободного текста (dispatch_text в message_router.py)

  Вызывается только при StateFilter(None) — когда пользователь НЕ в LogState.
  Если пользователь в LogState, его текст идёт в handle_log_entry (log_handler).

  Шаг | Триггер                                        | Действие
  -----+------------------------------------------------+---------------------------
  FSM  | PingState.waiting_response                     | memory_router → _bot/file
  0    | _QUESTION_RE: ?, "не вижу", "почему", "куда"  | → LLM
  0.5  | _CONVERSATION_RE: "ок", "нет, не надо"         | → LLM как чат
  1    | _OBSIDIAN_LOG_FULL_RE: "запиши в питание: текст"| → прямой append без LLM
  2    | _OBSIDIAN_LOG_RE: "запиши в питание" (без текста)| → LLM уточнит
  3    | _LOG_CONTINUATION_RE + кэш 15 мин: "ещё съел" | → прямой append без LLM
  4    | _FACT_VERBS_RE: съел/спал/купил/позвонил...    | → LLM (complete или log)
  4.5  | _MEAL_NOUN_RE: начало с завтрак/обед/ужин      | → LLM (log или task)
  5    | COMMAND_KEYWORDS: покажи/перенеси/удали/запомни | → LLM
       |   + поставь/измени/поменяй/переименуй          |
  5.5  | _CONTEXT_EDIT_RE: "ей/её/эту" (только местоим) | → LLM (move_task)
  5.7  | _READ_REQUEST_RE: прочитай/что записалось       | → LLM (read_bot_log)
  6    | Fallback: rule-based parse_task()              | → карточка confirm/reject

  Инструменты LLM (tool_registry.py)

  Инструмент                              | Назначение
  ----------------------------------------+------------------------------------------
  create_task(text, date, time?)          | Создать задачу → confirmed + Google Cal
                                          | После ответа LLM → автоматически карточка

  delete_task(task_id/text/ids[])         | Удалить (батч)

  set_category(task_id/text, category)    | Категория: inbox/work/personal/health/...
  get_today_plan(date?)                   | Список задач на дату (null = сегодня)
  append_obsidian_log(sphere, entry)      | Записать факт в лог-файл сферы
  read_bot_log(filename)                  | Прочитать последние 15 строк _bot/file
  save_fact_to_obsidian(fact)             | Постоянный факт → _bot/bot_memory.md
  read_memory_from_obsidian()             | Вся память из bot_memory.md

  Батч: task_ids=[id1, id2] для complete/delete.
  Поиск: task_text → resolve_task_reference() → fuzzy LIKE-поиск по SQLite.

  ---
  Долгосрочная память (bot_memory.md)

  Факты о пользователе хранятся в {obsidian_vault_path}/_bot/bot_memory.md.

  READ (каждый запрос): read_memory_sync() — TTL-кэш 5 минут (in-process dict).
    При сохранении нового факта: invalidate_memory_cache() сразу сбрасывает кэш.
    Следующий запрос прочитает обновлённый файл.

  INJECT в промпт: build_obsidian_memory() в prompt_builder.py
    — читает через кэш, последние 15 фактов из файла
    — вставляется в system-сообщение перед legacy SQLite-памятью

  SAVE: save_fact_to_obsidian(fact) → appends "- [YYYY-MM-DD] Факт: ..." + git sync

  ---
  Структурированные логи (SQLite log_entries)

  Каждая запись в Obsidian параллельно дублируется в БД для аналитики.

  Таблица log_entries (db.py → LogEntry):
    id, user_id, sphere, raw_text, logged_at (YYYY-MM-DD HH:MM), created_at

  Запись: _write_log_entry() в obsidian_tools.py
    — вызывается из append_obsidian_log() и append_to_bot_log()
    — открывает отдельную SessionLocal — не блокирует основной коммит

  Чтение: LogRepo(session).get_recent(user_id, sphere?, days, limit)
    — фильтрует по cutoff date и sphere
    — используется инструментом query_logs

  Инструмент query_logs:
    — sphere: "sleep" / "nutrition" / "training" / "german" / "health" и т.д.
    — days: глубина выборки (по умолчанию 7)
    — возвращает список в хронологическом порядке

  FSM Персистентность (storage/fsm_storage.py)

  SQLiteFSMStorage(BaseStorage) — заменяет MemoryStorage (состояния не теряются при рестарте).

  Файл: data/fsm.db (отдельно от tasks.db)
  Режим: WAL (concurrent reads)
  Ключ: "{bot_id}:{chat_id}:{user_id}:{destiny}"

  Инициализация в main.py:

    storage = SQLiteFSMStorage(fsm_db)
    dp = Dispatcher(storage=storage)

  FSM Плановые пинги (ping_service.py + memory.py)

  1. send_scheduled_ping(bot, storage, question, filename)
     — отправляет вопрос пользователю
     — устанавливает PingState.waiting_response через FSM storage
     — сохраняет filename в FSM data
  2. memory_router перехватывает ответ (зарегистрирован ПЕРВЫМ в main.py)
  3. Пишет через append_to_bot_log(filename, text) — без SPHERE_MAP
     — дублирует запись в log_entries SQLite

  ---
  История диалога и State Injection

  build_messages() → системный промпт из блоков:
    1. build_system_prompt() — правила LLM, дата/время, таймзона
    2. build_obsidian_memory() — последние 15 фактов из bot_memory.md (TTL-кэш)
    3. build_memory_context() — legacy SQLite-память (MemoryItem)
    4. build_day_summary() — предстоящие задачи с id, датой, временем, статусом
    5. build_done_history() — последние 5 выполненных задач

  Стек сообщений: [system] + dialog_repo.get_recent(20) + [current_user_msg]
  Фильтр: системные ошибки не попадают в dialog_history.

  Правила в системном промпте по задачам (4 уровня приоритета):
    1. task_id из предыдущего tool-response → использовать его
    2. Если нет ID, но есть task_text → resolve_task_reference()
    3. Если явно упомянут текст задачи → искать по тексту
    4. Использовать context clues (местоимения, "это", "её")

  ---
  Google Calendar (domain/google_calendar.py)

  Операции: create_event, update_event, delete_event, rename_event, mark_done
  JSON Merge Patch: events().patch() — меняет только нужные поля (summary, start, end)

  ФИКС midnight crossing:
    Если end_time < start_time (например, 23:00 + 1ч → 00:00),
    end_date сдвигается на следующий день. Иначе Google API возвращает
    "timeRangeEmpty" 400 error.

  Поле google_event_id в Task хранит event ID из Google Calendar.
  create_task в tool_executor: при ошибке Google — задача сохраняется только в SQLite.

  Карточки задач (tasks.py)

  _build_card: 3-строчный HTML-формат:
    📅 Дата | ⏰ Время / весь день | [статус]
    📝 Текст задачи
    🗂 Категория

  _build_keyboard: 2 ряда инлайн-кнопок:
    [✏️ Дата] [🕐 Время]
    [📝 Название] [🗑 Удалить]

  После LLM-создания задачи (create_task tool call):
    _run_llm_chat() отслеживает created_task_ids из tool-ответов,
    после текстового ответа LLM отправляет карточки для всех созданных задач.

  Ловушки и инварианты

  ПОРЯДОК РОУТЕРОВ в main.py:
    memory_router → log_router → main_router
    Нарушение → FSM-ответы на пинги попадают в dispatch_text

  СОСТОЯНИЯ FSM:
    В LogState.* dispatch_text не вызывается (StateFilter(None) не проходит).
    В PingState.waiting_response перехватывает memory_router до log_router.
    FSM персистентен через SQLiteFSMStorage — состояние сохраняется при рестарте.

  ПУТИ OBSIDIAN:
    Path(settings.obsidian_vault_path) / "_bot" / filename — не менять.

  GIT SYNC:
    Порядок операций: add → commit → pull --rebase → push (не pull до commit!)
    Иначе "Your local changes would be overwritten by merge"
    Все git-операции сериализованы через _GIT_LOCK.

    Кнопка [↩ Отменить] — инлайн, работает независимо от FSM-состояния.

Фазы к 100%

  Фаза 1 — Структурированные данные ~15%
  LLM извлекает нутриенты/нагрузку из свободного текста при записи.
  - «200г лосося, поел норм» → запись 44г белка, 240ккал в structured_data
  - «присед 5x5 120кг» → {exercise: squat, weight: 120, sets: 5, reps: 5}
  - Добавляет JSON-колонку в log_entries
  - После этого analyze_logs считает реальный суммарный белок за день/неделю

  Зависимость: всё остальное опирается на эту фазу.

  ---
  Фаза 2 — Проактивные алёрты ~15%
  Фоновый джоб анализирует паттерны и пишет первым.
  - Белок < цели 3 дня подряд → сообщение вечером
  - Тренировка пропущена 3 раза → флаг
  - Немецкий streak под угрозой → напоминание
  - Румынский не появлялся N дней → приоритет (дедлайн по гражданству)

  Требует: Фаза 1 (иначе нечего анализировать).

  ---
  Фаза 3 — Оценка текущего состояния ~15%
  Бот знает насколько ты сейчас «в ресурсе».
  - Вечерний пинг: «энергия 1-10?» → хранится
  - Инференс: сон < 6ч + поздний отбой → завтра «низкий ресурс»
  - Пользователь говорит «я уставший» → учитывается в рекомендациях
  - Ключ к адаптивности: одни и те же цели, разная интенсивность под
  состояние

  ---
  Фаза 4 — Чтение Google Calendar ~10%
  - Видеть свободные окна сегодня/завтра
  - Утренний план включает встречи из GCal рядом с задачами
  - «В 16:00 у тебя час свободен — хватит на немецкий»

  Это GCal Level 1 который ты отложил — станет нужен здесь.

  ---
  Фаза 5 — «Один следующий шаг» ~20%
  Синтез всего: состояние + календарь + протоколы + активные задачи → одна
  конкретная рекомендация.
  - Утром или по запросу «что мне сейчас делать?»
  - Учитывает ресурс: выжат → 15 мин немецкого или спать раньше; в форме →
  сложная задача или тренировка
  - Пуш сам или по запросу
